# 実行役プロンプト・仕様書テンプレート

指示役が実行役（Sonnet/Haiku）に渡すプロンプト・仕様書の雛形。
あなたが手動で使う必要はないが、体制の中身を透明化するために残す。

## T1. Sonnet向け実装仕様書【主力・S1用】

指示役がヒアリング結果からこの形式の仕様書を作り、Sonnetに発注して実装させる。

```
# 実装依頼：{ツール名}

## 目的
{例：月次の売上データを集計し、取引先ごとの請求書PDFを自動生成する}

## 環境
Google スプレッドシート + Google Apps Script
（依頼者がExcel指定の場合：Excel + VBA。バージョン：{確認したバージョン}）

## 入力
- シート「{名前}」：{列定義。例：A=日付, B=取引先名, C=品目, D=金額}
- {その他の入力：フォーム、CSVなど}

## 出力・機能
1. {機能1。例：メニューに「請求書作成」ボタンを追加}
2. {機能2。例：取引先ごとに請求書シートを生成し、PDFでDriveの指定フォルダに保存}
3. {機能3}

## 制約
- 非エンジニアが使う。実行はボタン（カスタムメニュー）1つで完結させる
- エラー時は処理を止めず、問題のあった行を「エラー一覧」シートに出す
- 外部API・外部サービスへの通信はしない（顧客データを外に出さない）
- コード内に日本語コメントを付ける（依頼者側で改修できるように）

## 受け入れ条件
- 添付のテストデータ{N}件で期待出力と一致すること
- 0件データ・空行・金額が空のケースでエラー落ちしないこと
```

## T2. テストデータ生成（Haiku）

```
以下の列構成のテストデータをCSVで{N}件生成してください。すべて架空のデータにすること。

列構成：{列定義}

含めるべきケース：
- 正常データ（8割）
- 異常系：空欄あり／日付形式ゆれ／金額が0や負数／同名の別取引先（2割）

実在の企業名・人名は使わない（「株式会社サンプルA」「試験太郎」等にする）。
```

## T3. 使い方マニュアル作成（Sonnet）

```
非エンジニアの事務担当者向けに、以下のツールの使い方マニュアルを作成してください。

ツールの機能：{仕様書を貼る}

要件：
- 「初回設定」「毎回の操作」「困ったとき」の3章構成
- 1手順1動作。専門用語を使う場合は一行の補足を付ける
- スクリーンショット挿入位置を【画面：◯◯の状態】形式で指定（撮影は人間が行う）
- 「困ったとき」には想定エラー3つと対処を載せる
```

## T4. 業務改善提案書ドラフト（Sonnet／S2用）

```
業務ヒアリングのメモから、業務改善提案書のドラフトを作成してください。

要件：
- 構成：現状の業務フロー図（テキスト）→ 課題の整理 → 改善案（自動化する範囲としない範囲を明確に）→ 概算費用と期待効果（削減時間の試算）
- 「すべて自動化」を提案しない。費用対効果が低い部分は「手作業のまま運用を整える」提案にする
- 経営者が読んで投資判断できる粒度にする

--- ヒアリングメモ ---
{メモ}
```

## T5. 記事ドラフト（Sonnet／S3用）

```
{媒体名・想定読者}向けの記事「{タイトル}」のドラフトを執筆してください。

要件：
- 構成案：{Haikuが作った構成 or 指示役の構成}
- 文字数：{N}字
- 実務経験者の監修が入る前提。断定が必要な技術的記述には【要監修】マークを付ける
- 検索上位の焼き直しにならないよう、現場目線の具体例枠を各見出しに1つ設ける（中身は監修者が記入）
```

## T6. 体裁統一・定型処理（Haiku）

```
以下の文書を{指定形式}に変換してください。
- 表記ゆれを統一（{統一ルール}）
- 内容の追加・削除・言い換えはしない
```

## 使い方の実際

これらのテンプレートを手動で運用する必要はない。案件文とヒアリング結果をこのセッションに貼れば、
指示役が適切なテンプレートを選び、Sonnetに実装させ、テストデータ・マニュアルまで一式そろえて返す。
あなたの作業は「できたツールを動作確認する → 結果を戻す」だけ。
