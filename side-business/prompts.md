# 実行役プロンプト・仕様書テンプレート

指示役が実行役（Sonnet/Haiku）に渡すプロンプトの雛形と、Codexに渡す仕様書の雛形。
あなたが直接使う必要はないが、体制の中身を透明化するために残す。

## T1. 記事監修・疑義リスト抽出（Haiku）

```
あなたは通信インフラ記事のファクトチェック補助者です。
以下の記事から、技術的な正確性の確認が必要な記述をすべて抽出してください。

出力形式（表）：
| # | 該当箇所（原文引用） | 論点 | 確認すべきこと |

注意：
- 正誤の判定はしない（判定は現場経験者が行う）
- 数値・規格名・技術用語・因果関係の説明をすべて拾う
- 曖昧な表現（「一般的に」「ほとんどの場合」等)も対象にする

--- 記事本文 ---
{記事}
```

## T2. 監修コメント清書（Sonnet）

```
通信インフラの現場経験者による監修判定メモを、依頼者に納品できる
「監修指摘リスト」に清書してください。

要件：
- 各指摘は「指摘箇所／問題点／修正案／根拠の説明」の4項目
- 専門用語には一行の補足を付け、非エンジニアの編集者が読めるようにする
- トーンは丁寧かつ簡潔。批判的にならない
- 判定メモにない内容を追加しない（推測での加筆禁止）

--- 判定メモ ---
{本人の監修メモ}
--- 元記事 ---
{記事}
```

## T3. 技術文書ドラフト（Sonnet）

```
中小の電気通信工事会社向けの「{文書名}」のドラフトを作成してください。

前提：
- 業界一般の知識のみで構成する（特定事業者固有の手順は書かない）
- 想定読者：{読者}
- 様式：{様式・章立ての指定}
- 各項目に、現場経験者が実体験を書き足すための【監修者追記欄】を設ける

完成度目標：監修者が追記・修正するだけで納品できる状態（体裁の手直し不要）
```

## T4. 体裁統一・様式展開（Haiku）

```
以下の文書を{Excel向けのチェックリスト形式／指定テンプレート}に変換してください。
- 表記ゆれを統一（{統一ルール}）
- 項目の粒度を揃える（1項目1動作）
- 内容の追加・削除・言い換えはしない
```

## T5. 資格教材の章ドラフト（Sonnet）

```
{資格名}の対策教材の「{章タイトル}」を執筆してください。

要件：
- 出題範囲：{範囲}
- 構成：要点解説 → 頻出ポイント → 例題3問（解説付き）
- 「現場ではこう使う」というコラム枠を各節に1つ設ける（中身は空欄。監修者が実体験を記入）
- 教科書の丸写しにならないよう、初学者のつまずきポイント起点で説明する
```

## T6. Codex向け仕様書テンプレート（ツール実装）

指示役がこの形式で仕様書を書き、あなたがCodexに貼り付けて実装させる。

```
# 実装依頼：{ツール名}

## 目的
{例：基地局点検結果の集計と未実施項目の自動抽出}

## 環境
Google スプレッドシート + Google Apps Script（依頼者がExcel指定ならVBA）

## 入力
{シート構成・列定義}

## 出力・機能
1. {機能1}
2. {機能2}

## 制約
- 手作業での運用を想定し、ボタン1つで実行できること
- エラー時は処理を止めず、エラー行の一覧を別シートに出すこと
- 外部サービスへの通信はしない（顧客データを外に出さない）

## 受け入れ条件
- サンプルデータ{N}件で期待出力と一致すること
```

## 使い方の実際

これらのテンプレートを手動で運用する必要はない。案件文をこのセッションに貼れば、
指示役が適切なテンプレートを選び、実行役に振り分けて初稿まで自動で進める。
