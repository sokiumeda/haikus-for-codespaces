# 副業事業計画：業務効率化・自動化サービス × AI増幅

**前提条件**
- 本人：インフラ運用の実務経験あり＋プログラミングが多少できる（本業ではない）
- 稼働時間：週5時間以内
- 体制：指示役 = 上位モデル（Claude）／実行役 = Sonnet・Haiku（タスクにより切替）／コード = Codex
- 人間の役割：受注のやり取り・動作確認・納品のみ。コードの大部分はAI側が書く

---

## 1. 事業コンセプト

**「Excel・スプレッドシート・GASによる業務自動化」を主力商品にする。**

選定理由：
1. **市場が大きい**：クラウドソーシングで最も案件数が多いジャンルの一つ。中小企業・個人事業主の「手作業をなんとかしたい」需要は定常的
2. **AI増幅と最も相性が良い**：コードはCodex＋実行役が書く。人間に必要なのは「要件を聞き取る」「動作を確認する」「納品する」の3つだけで、「多少できる」レベルで十分回る
3. **ストック化しやすい**：一度作ったツールはテンプレート商品として再販できる

インフラ運用の経験は「現場のオペレーション業務を理解している自動化屋」という
差別化要素として使う（点検・報告・シフト・集計など、運用現場の定型業務は自動化ニーズの宝庫）。

週5時間の内訳目安：

| 作業 | 時間/週 |
|---|---|
| 受注・要件の聞き取り（メッセージ対応） | 1.0h |
| AIが書いたツールの動作確認・修正指示 | 2.5h |
| 納品・使い方説明・請求 | 1.0h |
| 週次振り返り・出品改善 | 0.5h |

## 2. 収益目標（現実的なフェーズ設定）

受託（時間単価型）で実績と実効時給を上げつつ、テンプレート商品（ストック型）を育て、
稼働時間を増やさずに収益が伸びる構造にする。

| フェーズ | 期間 | 月間目標 | 主な収益源 |
|---|---|---|---|
| 1. 実績づくり | 〜3ヶ月 | 3〜6万円 | 小規模な自動化案件（1〜2万円）を月2〜3件 |
| 2. 単価向上 | 4〜6ヶ月 | 10〜18万円 | 中規模案件（3〜5万円）＋リピート・保守契約 |
| 3. 資産化 | 7〜12ヶ月 | 18〜30万円 | テンプレート販売＋カスタマイズ受注の二段構え |
| 4. 本業並み | 12ヶ月〜 | 30万円〜 | ストック収益が過半。稼働時間は据え置き |

## 3. 90日ロードマップ

**Week 1-2：開店準備**
- ココナラ・クラウドワークスのアカウント開設、プロフィール整備（→ `sales-templates.md`）
- サービス3種を出品（→ `service-menu.md`）
- ポートフォリオ用のデモツールをAI側で3点制作、本人が動作確認
  （例：勤怠集計の自動化、請求書の自動生成、フォーム回答の自動仕分け）

**Week 3-6：初受注**
- クラウドワークスの「GAS」「スプレッドシート」「Excel マクロ」案件に週3〜5件提案
- 小規模案件を低めの価格で3件受注し、評価を貯める

**Week 7-12：単価を上げる**
- 実績を根拠に単価を1.5〜2倍に改定
- 納品済みツールの汎用版をテンプレート商品として出品（第1弾）
- リピーターに月額の保守・改修プランを提案

## 4. ファイル構成

| ファイル | 内容 |
|---|---|
| `service-menu.md` | サービスメニューと価格表 |
| `sales-templates.md` | プロフィール文・出品文・提案文のテンプレート |
| `operations.md` | 指示役/実行役の分担とモデル切替ルール、週次の回し方 |
| `prompts.md` | 実行役（Sonnet/Haiku）と Codex に渡すプロンプト・仕様書テンプレート |

## 5. 必ず守ること（コンプライアンス）

1. **勤務先の副業規定を先に確認する。** 許可制の会社が多い
2. **守秘義務。** 勤務先の業務データ・手順・顧客情報は使わない。デモツールもすべて架空データで作る
3. **顧客データの扱い。** 受託時に預かるデータは案件終了後に削除し、外部サービスに送らない（AIに顧客の実データを貼らないのが原則。構造だけ伝えて架空データでテストする）
4. **年間所得20万円超で確定申告**が必要（住民税は金額によらず申告）
5. AIが書いたコードは必ず本人が動作確認してから納品する。無確認の納品は事故のもと
