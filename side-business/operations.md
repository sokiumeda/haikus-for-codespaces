# 運用体制：指示役・実行役の分担とモデル切替ルール

## 体制図

```
あなた（受注・要件聞き取り・動作確認・納品）
   │  案件内容とヒアリング結果を貼るだけ
   ▼
指示役：Claude 上位モデル（このセッション）
   │  要件の仕様書化・タスク分解・成果物レビュー
   ├──▶ 実行役 Sonnet …… GAS/マクロ/関数の実装、改善提案書・マニュアル・記事のドラフト
   └──▶ 実行役 Haiku  …… テストデータ生成・体裁統一・定型文・チェックリスト展開
```

## モデル切替ルール

| タスクの性質 | 担当 | 理由 |
|---|---|---|
| 要件の解釈・仕様書化・成果物の品質判定 | 指示役（上位モデル） | ここのミスが全工程に波及するため最上位で行う |
| GAS・Excelマクロ・関数の実装 | Sonnet | コード担当。指示役が仕様書（`prompts.md` T1）を作って発注する |
| マニュアル・提案書・記事のドラフト、コードの説明文 | Sonnet | 文書品質と速度のバランスが最良 |
| テストデータ（架空データ）生成、表記統一、定型返信の差し込み、チェックリスト展開 | Haiku | 高速・低コスト。判断を要しない処理はすべてここへ |

**運用原則**
1. まずHaikuで足りるか考え、足りない場合のみSonnetに上げる（コスト最小化）
2. コードは「Sonnetが実装 → 指示役がレビュー → あなたが実データ相当の架空データで動作確認」の三段でチェックする
3. 顧客の実データをAIに貼らない。列構成だけ伝え、テストはHaikuが作った架空データで行う
4. あなたが手を動かすのは「動作確認」と「顧客対応」だけ。コードの手直しが必要なら不具合の内容を指示役に伝え、Sonnetにやり直させる

## 実際の回し方（このセッションの使い方）

案件を受注したら、このセッション（またはClaude Codeの新セッション）に以下を貼るだけでよい：

> 案件：◯◯（依頼内容・ヒアリング結果・希望納期を貼り付け）
> → 仕様書とテストデータと初版マニュアルまで作って

指示役が仕様書を作ってSonnetに実装させ、テストデータ・マニュアル初稿まで
そろえて返す。あなたは動作確認をして結果をこのセッションに戻すだけで、
修正版や納品文までこちらで整える。**実装が外部ツールを経由しないため、
コピペの往復作業は発生しない。**

## 週次サイクル（合計5時間の使い方）

| 曜日目安 | 作業 | 時間 |
|---|---|---|
| 月 | 新着案件チェック・提案文送信（週3〜5件） | 45分 |
| 水 | 受注案件の要件をAIに投入・実装結果の動作確認 | 2時間 |
| 土 | 最終確認・マニュアル添付・納品・請求 | 1.5時間 |
| 土 | 週次振り返り（受注率・単価・評価を記録） | 15分 |
| （随時） | 顧客メッセージ返信（定型文使用） | 30分 |

## 品質チェックリスト（納品前に毎回）

- [ ] 本人が架空データで一連の操作を通しで実行し、期待どおり動いたか
- [ ] 異常系を1つは試したか（空行・想定外の値・0件データ）
- [ ] マニュアルだけ読んで依頼者が操作できるか（画面キャプチャ付きか）
- [ ] 顧客の実データ・固有名詞がAIへの入力やテストファイルに混入していないか
- [ ] 依頼者の環境（Excelのバージョン／Googleアカウント権限）で動く前提になっているか

## KPI（毎週土曜に記録）

- 提案数 / 受注数（受注率20%を下回ったら提案文を改訂）
- 実効時給 = 週の売上 ÷ 実稼働時間（フェーズ2で3,000円、フェーズ3で6,000円が目安）
- 評価件数と平均点（4.8を下回ったら品質工程を見直す）
- リピート・保守契約数（フェーズ2以降の重点指標）
