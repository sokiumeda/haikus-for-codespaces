# 運用体制：指示役・実行役の分担とモデル切替ルール

## 体制図

```
あなた（受注・専門監修・納品）
   │  案件内容を貼るだけ
   ▼
指示役：Claude 上位モデル（このセッション）
   │  タスク分解・品質基準の設定・成果物レビュー
   ├──▶ 実行役 Sonnet …… 構成設計・本文ドラフト・修正コメント清書
   ├──▶ 実行役 Haiku  …… 疑義リスト抽出・体裁統一・定型文量産・要約
   └──▶ Codex（外部）…… Excel/GAS/スプレッドシートの自動化実装
                         （指示役が仕様書を書き、あなたがCodexに渡す）
```

## モデル切替ルール

| タスクの性質 | 担当 | 理由 |
|---|---|---|
| 案件の解釈・タスク分解・品質判定 | 指示役（上位モデル） | 判断ミスが全工程に波及するため最上位で行う |
| 文書の構成設計、技術的ドラフト、推敲 | Sonnet | 品質と速度のバランスが最良 |
| チェックリスト展開、表記統一、要約、テンプレ差し込み、大量の定型処理 | Haiku | 高速・低コスト。判断を要しない処理はすべてここへ |
| 表計算の関数・マクロ・GAS・小さなツール実装 | Codex | コード担当（本環境からは直接呼べないため、指示役が仕様書を作成しあなたが実行） |

**運用原則**
1. まずHaikuで足りるか考え、足りない場合のみSonnetに上げる（コスト最小化）
2. 実行役の成果物は必ず指示役がレビューしてから、あなたの監修に回す（あなたの5時間を守るため、明らかな不備はAI側で潰す）
3. あなたが直すのは「実務知識がないと判定できない箇所」だけ。てにをは修正はAIに差し戻す

## 実際の回し方（このセッションの使い方）

案件を受注したら、このリポジトリのセッション（またはClaude Codeの新セッション）で指示役に以下を貼るだけでよい：

> 案件：◯◯（依頼内容・元記事・希望納期を貼り付け）
> 成果物：S1の指摘リスト形式で
> → 実行役に振り分けて初稿まで作って

指示役がSonnet/Haikuサブエージェントに分配し、レビュー済みの初稿を返す。
あなたは監修コメントを返すと、修正版が納品形式で出てくる。

## 週次サイクル（合計5時間の使い方）

| 曜日目安 | 作業 | 時間 |
|---|---|---|
| 月 | 新着案件チェック・提案文送信（週3件） | 30分 |
| 水 | 受注案件をAIに投入・初稿の監修 | 2時間 |
| 土 | 修正版の最終確認・納品・請求 | 1.5時間 |
| 土 | 週次振り返り（受注率・単価・評価を記録） | 30分 |
| （随時） | 顧客メッセージ返信（定型文使用） | 30分 |

## 品質チェックリスト（納品前に毎回）

- [ ] 技術的な誤りがないか（本人監修済みか）
- [ ] 勤務先固有の情報・数値・固有名詞が混入していないか
- [ ] 依頼者の指定形式（文字数・様式・トーン）に合っているか
- [ ] AI特有の冗長表現・断定しすぎ表現が残っていないか
- [ ] 根拠を聞かれたら答えられる内容だけになっているか

## KPI（毎週土曜に記録）

- 提案数 / 受注数（受注率20%を下回ったら提案文を改訂）
- 実効時給 = 週の売上 ÷ 実稼働時間（フェーズ2で3,000円、フェーズ3で6,000円が目安）
- 評価件数と平均点（4.8を下回ったら品質工程を見直す）
